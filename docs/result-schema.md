# Video Digest – схема результата, пресеты, блоки

Версия 0.1. Это контракт между LLM-этапом (промпты), базой (`jobs.result`) и фронтом (страница результата и экспорт). Меняется только здесь, остальное подстраивается.

Машинный вариант – `schemas/result.schema.json` (JSON Schema 2020-12), его используют n8n и фронт. Правила п. 9, которые не выражаются схемой, проверяет `n8n/scripts/validate_result.py`. При расхождении главный – этот markdown, схему подтягивают под него.

## 1. Принципы

- Результат – один JSON. Фронт рендерит блоки по наличию, экспорт в md / pdf / html генерируется из того же JSON.
- Каждый блок – самостоятельный. LLM-этап заполняет их отдельными вызовами, падение одного блока не ломает остальные.
- Всё, что ссылается на видео, несёт таймкод в секундах. Фронт делает его кликабельным.
- Модель никогда не пишет свободный markdown внутрь JSON. Только строки, массивы, числа. Форматирование – забота фронта.
- Язык видео определяется автоматически, язык результата выбирает пользователь (по умолчанию = язык видео). Транскрипт всегда остаётся на языке оригинала.

## 1.1 Язык

Определение – каскадом, дешёвое первым:

1. `/probe`: yt-dlp отдаёт `language` из метаданных и языки субтитров. Если есть ручные субтитры – их язык и есть язык видео, уверенность 1.0.
2. Whisper при транскрибации первого чанка возвращает язык и вероятность. Это основной источник для видео без субтитров.
3. Если уверенность ниже 0.7 (смешанная речь, музыка в начале) – прогнать язык-детект по первым 60 секундам очищенного текста через LLM.

Результат пишется в `source.language` (ISO 639-1), `language_detected_by` (`subtitles` | `whisper` | `request` | `llm`; `request` – язык взят из задачи как есть, STT его не проверял: так работает Deepgram, которому код языка передаётся параметром и который ничего не детектит), `language_confidence` (`null`, если провайдер не отдаёт вероятность, как OpenAI whisper-1 и Deepgram с заданным языком). На карточке после `/probe` показываем «Язык: русский» с возможностью поправить руками – ошибка детекта до транскрибации дешевле, чем после.

`output_language` – параметр задачи, выбирается на шаге опций. По умолчанию равен `source.language`. Если отличается – все LLM-вызовы для `digest` и `extras` получают инструкцию писать на этом языке, отдельного этапа перевода нет. `transcript.clean` не переводится – это оригинал, по нему проверяются цитаты. Цитаты в `digest.quotes` при `output_language != source.language` даются в оригинале плюс поле `translation`.

Перевода транскрипта целиком нет. Опция `transcript_translation` стояла в контракте с 4 сентября и ни разу не была реализована: пайплайн писал `translated: null` константой, включая j_k3c1se от 10 сентября с этой опцией; снята 17 сентября вместе с полем. Схема следующего цикла: дайджест по оригиналу, перевод тезисов, заголовков и критики, цитата на языке источника с подстрочником – перевод транскрипта ломает дословность цитат, человек переходит по таймкоду и слышит другой язык.

## 1.2 Воспроизведение

Страница результата умеет перематывать источник по таймкоду. Как – зависит от `source.playback.kind`:

| kind | Что играет | has_video |
|---|---|---|
| `youtube`, `vk`, `rutube` | iframe официального плеера, перемотка через его API | true |
| `direct` | HTML5-плеер по исходному URL (mp4 / mp3) | по расширению |
| `audio` | наш аудиоплеер поверх `playback.mp3` из Media Service | false |

Для загруженных файлов всегда `audio`, даже если загрузили видео: храним только нормализованный mp3, ролик после обработки удаляется. `url` для `audio` – `/api/jobs/{id}/media`, отдаётся с поддержкой Range.

## 2. Верхний уровень

```json
{
  "schema_version": "1.0",
  "job_id": "j_8f2k1",
  "source": {
    "type": "url",
    "url": "https://...",
    "platform": "youtube",
    "title": "...",
    "duration_sec": 3721,
    "thumbnail_url": "...",
    "language": "ru",
    "language_detected_by": "whisper",
    "language_confidence": 0.98,
    "playback": {
      "kind": "youtube",
      "url": "https://www.youtube.com/embed/...",
      "has_video": true
    }
  },
  "preset": "lecture",
  "options": ["glossary", "critique"],
  "output_language": "ru",
  "transcript": { ... },
  "digest": { ... },
  "extras": { ... },
  "meta": { ... },
  "notices": [ { "kind": "transcript_shortened", "places": 37, "starts": [1357.5, 1364.1, ...] } ]
}
```

`notices` (с 23 сентября, необязательное) – то, что меняет прочитанное, для читателя, не для нас. Собирается на finalize из предупреждений clean: `kind` – вид, `places` – число мест, `starts` – их таймкоды по возрастанию, без повторов, не больше 40 (при `places` больше 40 список обрезан). Фрагментов речи здесь нет и быть не должно: тексты потерянных фраз лежат в `jobs.meta.quality_warnings` и событиях (решение от 17 сентября о чистке), а `notices` уезжают в `result` и в экспорт. Виды: `transcript_shortened` – после исправления кусок принят короче, чем допускает правило 10 (доля ниже 92% или потеряна единица от 10 слов, `starts` – таймкоды потерянных единиц); `clean_fallback` – кусок очищен правилами без модели (отказ провайдера по content filter или две невалидные попытки, `starts` – начала таких кусков). Стилевые пометки (родовые заголовки, мета-зачин `tldr`, части длиннее трети, повторы валидатора) в `notices` не попадают: они наше дело, не читателя. На странице – спокойная полоса под `tldr`: заголовок, число мест, «Показать места» раскрывает таймкоды, которые перематывают плеер; в `digest.md` и `transcript.md` – та же оговорка строкой с местами.

## 3. Transcript

Два представления: сегменты с таймкодами (для вкладки «Транскрипт» и srt) и очищенный текст по абзацам (для чтения и экспорта).

```json
"transcript": {
  "origin": "whisper",
  "segments": [
    { "start": 12.4, "end": 15.1, "text": "...", "speaker": "0:1" }
  ],
  "clean": [
    { "start": 12.4, "text": "Абзац очищенного текста без слов-паразитов и оговорок." }
  ],
  "stats": { "words": 8420, "segments": 842, "speakers": null }
}
```

`origin`: `subtitles_manual` | `subtitles_auto` | `whisper` | `deepgram`. `speaker` – `null` у субтитров и whisper (говорящих не разделяют). У Deepgram – строка `"<кусок>:<номер>"`, например `"2:0"`: номер аудио-куска (нарезка по 600 с) и номер говорящего внутри него. Нумерация локальна для куска: Deepgram нумерует говорящих внутри одного запроса, поэтому `"0"` в куске 1 и `"0"` в куске 2 – не обязательно один человек; сквозной идентификации говорящих нет, и поле не должно читаться так, будто она есть. Поэтому с 17 сентября поле есть в данных, но не показывается: фронт его не выводит, в экспорте (`result.json` внутри zip; md, srt и html сегментов с говорящими и не содержали) оно `null`. Основание – совещание j_4ac6yf: 19 номеров на встречу, где людей меньше десяти, и на каждом стыке кусков речь одного человека идёт под новым номером; подписи, похожие на атрибуцию и не являющиеся ею, хуже отсутствия подписей. Вернём, когда нумерация станет сквозной. `stats.speakers` – всегда `null`: число говорящих мы не измеряем (whisper не разделяет никого, у Deepgram нумерация локальна), а правдоподобная константа хуже пустого значения.

Чистка (`clean`) – первый LLM-вызов, по чанкам. Правила промпта: убрать паразиты и повторы, склеить обрывки, исправить очевидные ошибки распознавания по контексту, НЕ сокращать и НЕ пересказывать. Абзац начинается на смене мысли, `start` – таймкод первого сегмента абзаца.

## 4. Digest – основная выжимка

Обязательные блоки, есть во всех пресетах.

```json
"digest": {
  "tldr": "Три-четыре предложения: о чём видео и главный вывод.",
  "key_points": [
    { "text": "Тезис одной фразой.", "detail": "Одно-два предложения раскрытия.", "start": 245.0 }
  ],
  "structure": [
    { "title": "Название части", "start": 0, "end": 612.5, "summary": "О чём эта часть." }
  ],
  "quotes": [
    { "text": "Дословная цитата на языке оригинала.", "translation": null, "start": 1020.3, "speaker": null }
  ]
}
```

- `tldr` – до 80 слов.
- `key_points` – 5–12 штук (для видео короче двух минут 1–12, короче четырёх 3–12; минимум по длительности, с 21 сентября), по убыванию важности. `start` обязателен: тезис без места в видео не принимается.
- `structure` – оглавление, 3–10 частей (для видео короче двух минут 1–10, короче четырёх 2–10; минимум зависит от длительности, с 21 сентября), отсортированных по `start`, покрывают 0…`duration_sec` без дыр и наложений: `end` части равен `start` следующей, последняя заканчивается ровно на `duration_sec`. Если у видео есть главы (yt-dlp их отдаёт) – взять их за основу. Тезисы, цитаты и пометки привязываются к части `structure` по `start` – фронт использует это для раскрытия глав.
- `quotes` – 3–8 (короче двух минут 1–8, короче четырёх 2–8), только дословные фрагменты из `transcript.clean`, все разные. Проверяется программно: цитата должна найтись в тексте, иначе выкидывается; повтор уже принятой цитаты выкидывается тоже.

## 5. Extras – блоки по пресету и опциям

Присутствуют только заказанные. Фронт рендерит по ключу.

```json
"extras": {
  "glossary": [
    { "term": "...", "definition": "Как термин используется в этом видео.", "start": 340.0 }
  ],
  "decisions": [
    { "text": "Что решили.", "start": 1800.0 }
  ],
  "action_items": [
    { "text": "Что сделать.", "owner": "Имя или null", "due": "срок или null", "start": 1820.0 }
  ],
  "questions": [
    { "text": "Открытый вопрос, который прозвучал, но не закрыт.", "start": 900.0 }
  ],
  "critique": {
    "strong": ["Что аргументировано хорошо."],
    "weak": [
      { "claim": "Утверждение.", "issue": "Почему слабо: нет данных / логический скачок / противоречие.", "start": 1500.0 }
    ],
    "missing": ["Что не было сказано, хотя ожидалось по теме."]
  },
  "self_check": [
    { "question": "Вопрос для самопроверки.", "answer": "Краткий ответ.", "start": 600.0 }
  ],
}
```

Проверка фактов (`fact_check`) снята 17 сентября: опция принималась и добавляла три минуты к оценке, этап всегда пропускался, промпт был заглушкой. Правило: опция, которая принимается и влияет на ожидание, но не выполняется, снимается до реализации.

Правила `critique`: критикуется логика и обоснованность, не факты. `weak` обязательно с таймкодом.

## 6. Пресеты

Пресет задаёт промпт для `digest`, набор `extras` по умолчанию и нужна ли диаризация. С 30 сентября пресет – набор умолчаний, а не запрет: на форме его блоки стоят галочками, любой можно снять, любой другой добавить; в задачу уходит итоговый `options`, и только он определяет блоки (`preset: lecture, options: []` – без глоссария и вопросов).

| Пресет | id | Extras по умолчанию (галочки на форме) | Акцент в digest |
|---|---|---|---|
| Лекция / обучающее | `lecture` | `glossary`, `self_check` | конспект, понятия, последовательность объяснения |
| Совещание | `meeting` | `decisions`, `action_items`, `questions` | что решили, кто что делает, что осталось открытым |
| Доклад / вебинар | `talk` | `critique` | тезисы, аргументы, что автор продаёт |
| Интервью / подкаст | `interview` | `quotes` расширенные, `questions` | позиции собеседников, где расходятся |
| Просто выжимка | `plain` | нет | нейтрально, минимум |

Диаризация (имена спикеров) – вторая итерация; в MVP пресеты `meeting` и `interview` работают без неё, модель различает участников по контексту, где может.

Опции – все шесть блоков: `glossary`, `critique`, `self_check`, `decisions`, `action_items`, `questions`; у каждого пресета показаны все, сначала его умолчания. Язык результата – отдельный селект над пресетами, не чекбокс. Форматы экспорта не являются опциями – отдаются всегда.

## 7. Meta – для страницы, слайда и будущих кредитов

```json
"meta": {
  "created_at": "2026-09-04T12:00:00Z",
  "finished_at": "2026-09-04T12:09:41Z",
  "stages": [
    { "name": "probe", "status": "done", "ms": 1800, "cost_usd": 0 },
    { "name": "download", "status": "done", "ms": 14000, "cost_usd": 0 },
    { "name": "transcribe", "status": "done", "ms": 23000, "cost_usd": 0.26, "provider": "deepgram/nova-3", "model_actual": "general-nova-3 2026-08-03.21876" },
    { "name": "clean", "status": "done", "ms": 40000, "cost_usd": 0.06, "model": "gpt-4o-mini", "model_actual": "gpt-4o-mini-2024-07-18" },
    { "name": "digest", "status": "done", "ms": 55000, "cost_usd": 0.11, "model": "map: gpt-4o-mini, reduce: gpt-5.6-luna", "model_actual": "map: gpt-4o-mini-2024-07-18, reduce: gpt-5.6-luna" },
    { "name": "extras", "status": "done", "ms": 70000, "cost_usd": 0.14, "model": "glossary: gpt-4o-mini, critique: gpt-5.6-luna", "model_actual": "..." },
  ],
  "total_cost_usd": 0.50,
  "tokens": { "in": 61000, "out": 9000 }
}
```

`model` – имя, которое запросили (`LLM_MODEL_MAP` / `LLM_MODEL_REDUCE`), `model_actual` – идентификатор из тела ответа провайдера: у OpenAI за алиасом стоит датированный снапшот (`gpt-4o-mini-2024-07-18`), а `gpt-5.6-luna` отдаёт сам алиас. Провайдеры молча двигают алиасы, без выпуска модели сравнения невоспроизводимы задним числом. Для `transcribe`: ответы whisper у OpenAI и Groq поля модели не содержат, записи нет; Deepgram отдаёт `metadata.model_info` с именем и версией сборки – пишется как `"<name> <version>"` (`general-nova-3 2026-08-03.21876`); сборка зависит от языка запроса – на `el` та же nova-3 отвечала версией `2026-06-19.2060`.


`stages` – источник и для прогресса на странице ожидания (тот же список, статусы меняются по ходу), и для слайда про стоимость, и для кредитов потом.

## 8. Экспорт

Из одного JSON:

- `digest.md` – tldr, оглавление, тезисы с таймкодами-ссылками на видео, цитаты, extras по порядку.
- `transcript.md` – `clean` с таймкодами в начале абзацев.
- `transcript.srt` – из `segments`.
- `digest.html` – то же, что md, но с оформлением; pdf печатается из html.
- `all.zip` – всё вместе плюс `result.json`.

Таймкод-ссылка для YouTube: `url&t=245s`, для VK и Rutube – свои форматы, для загруженного файла – просто `[04:05]`.

## 9. Валидация после LLM

Перед записью в базу:

1. JSON парсится по схеме (pydantic). Не парсится – одна повторная попытка с указанием ошибки, потом блок помечается `failed`, остальное сохраняется. Повтор – исправление, а не новый ответ: отклонённый ответ возвращается модели как её реплика вместе с текстом ошибки, она меняет только то, что названо в ошибке, и сохраняет остальное, включая уже проверенные таймкоды (новый ответ с нуля заново рискует по каждому жёсткому правилу, а второго повтора нет). Ответ, который не разобрался как JSON, повторяется с нуля. Ошибка для `digest` перечисляет все жёсткие нарушения разом – таймкоды тезисов, границы `structure`, переводы и нехватка цитат – каждое с правкой: попытка исправления одна, и нарушение, названное в одиночку, прячет за собой следующее (j_wrvonm: за дырами в `structure` стояли цитаты без `translation`, до которых проверка не доходила).
2. Все `start` в пределах `duration_sec`. Таймкоды берутся из транскрипта, не от модели: `transcript.clean[].start` – время сегмента, в котором найдены первые слова абзаца; таймкод модели служит лишь ориентиром поиска (дальше 5 с от любого сегмента – отклоняется; абзац длиннее ~250 слов тоже – в нём теряются все таймкоды внутри); все `start` в `digest` и границы `structure` – таймкоды абзацев `transcript.clean` (границы могут быть ещё 0 и `duration_sec`), расхождение больше 1 с – отклоняется, меньше – притягивается к точному значению.
3. `quotes[].text` находятся в `transcript.clean` (нечёткое совпадение, порог 0.9). Кандидаты цитат на этапе map проверяются по тексту своего куска: недословные выбрасываются, при нехватке (3 для видео из одного куска, 2 на кусок) – повтор. Кандидаты `sections` на этапе map – разбиение куска: после программной сортировки по `start` идут встык от первого абзаца куска до его конца (последняя секция, кончающаяся на старте последнего абзаца, программно дотягивается до конца куска – больше этот абзац никому не принадлежит), без дыр, наложений и вложенных частей (реклама внутри темы режет её на тему, рекламу, тему); нарушения перечисляются в одной ошибке с подсказкой правки – одна повторная попытка, после неудачной разбиение чинится программно (вложенная часть режет внешнюю, дыра отходит предыдущей части, края – границы куска) с записью в `jobs.meta.quality_warnings`. Заметки map – сырьё, жёстким остаётся правило 7 для `structure`. Ошибка map, как и ошибка `digest`, перечисляет все нарушения разом – таймкоды, разбиение секций, недословные цитаты (j_72549q: модель узнала только про дыру в секциях, а пять переведённых на русский цитат остались до второй попытки, которой уже не было); при недословных цитатах ошибка называет язык транскрипта и показывает одно дословное предложение из куска – gpt-4o-mini иначе переводит цитаты снова. В итоговом digest цитата, которая не найдена, начинается с указательного слова или повторяет тезис, выкидывается; ответ отклоняется, только если осталось меньше трёх. `quotes[].start` – `start` абзаца, в котором цитата найдена, не значение от модели. `critique.weak[].start` – абзац с лучшим совпадением содержательных слов `claim` (не меньше половины слов); если такого нет, остаётся таймкод модели. Остальные `start` в `extras` притягиваются к ближайшему абзацу, если он не дальше 1 с.
4. (снято 17 сентября вместе с `fact_check`.)
5. Длины: `tldr` ≤ 80 слов, `key_points` ≤ 12.
6. Язык `digest.tldr` совпадает с `output_language` (быстрый детект библиотекой). Не совпадает – одна повторная попытка.
7. `structure` отсортирована по `start` и покрывает 0…`duration_sec` без дыр и наложений. Сортировка программная (порядок в ответе данных не теряет), дальше все нарушения границ разом – дыра, наложение, вложенная часть, пустая часть – в одной ошибке, каждое с правкой, которая его закрывает (j_wrvonm: валидатор назвал только первое нарушение, «start второй части должен равняться end первой», модель исправила буквально – получила пустую часть, а три дыры дальше остались, второй попытки нет).
8. Если `output_language` отличается от `source.language`, у каждой цитаты `translation` обязателен и непуст; иначе `null`.
9. Стиль: `tldr` не начинается с мета-зачина («Видео посвящено», «В этом видео», «Лекция рассказывает», «This video», «In this talk») – сразу предмет и вывод; `structure[].summary` не начинается с мета-глагола («обсуждается», «рассматривается», «обзор»); `key_points[].text` – не перечисление свойств, не «X является популярным» и не «слова X являются напутствием» (это описание слов, а не утверждение); `key_points[].detail` – не пересказ спикера («Джобс отмечает, что X» → «X, потому что Y»); `key_points[].text` не совпадает нечётко (порог 0.8) ни с `quotes[].text`, ни с `quotes[].translation`; для `ru` тире « — » в ответах модели заменяется на « – » программно, кроме дословных полей; `structure[].title` – не родовая метка («Введение», «Заключение»), кроме «Реклама» и «Вступление канала»; `quotes[].text` не начинается с указательного слова («Это», «Этот», «This», «That», «It») – цитата понятна без абзаца вокруг. Проверяется регулярными выражениями, нарушение – одна повторная попытка; правила про цитаты не повторяют ответ, а выкидывают цитату (п. 3).
10. Удержание `clean` (мягкое). Единица – предложение поверх склеенного текста куска, а не строка входа: строки `[t] text` после CONTEXT склеиваются в один текст (у субтитров VK, где каждая реплика повторяется в следующей, повторяющийся хвост отбрасывается), текст режется по знакам конца предложения, таймкод единицы – начало сегмента, в котором лежит её первое слово. Если на 40 слов приходится меньше одного знака конца предложения, вход режется окнами по 15 содержательных слов – так идут все 13 кусков субтитров VK j_7etqho, пунктуации в них нет вовсе. Содержательные слова – всё, кроме паразитов языка вывода; списки отдельные для ru и en, у языка без списка не вычёркивается ничего. Единица – от 5 содержательных слов для ru и от 6 для остальных языков. Единица сохранилась, если не меньше трети её трёхсловных связок есть в ответе. Кусок уходит на исправление по любому из двух пунктов, каждый со своим префиксом, чтобы в событиях и на странице результата было видно, какой сработал: (а) `clean_retention` – сохранилось меньше 92% единиц, ошибка перечисляет пропавшие единицы с таймкодами (до 15); (б) `clean_lost_long` – потеряна хотя бы одна единица от 10 содержательных слов, ошибка перечисляет их (до 10). Кусок короче 10 единиц не оценивается. После неудачного повтора укороченный текст принимается с записью в `jobs.meta.quality_warnings` и событием `clean_retention_low` – хуже полного, лучше отсутствия результата. На второй попытке отдельно считается «потеряно заново» (`clean_lost_after_fix`): единица, которой не было среди потерянных первой попыткой, засчитывается, только если она не прошла проверку по связкам И покрытие её содержательных слов в тексте второй попытки ниже 60% в окне полуторной длины – перепунктуация и слияние с соседним предложением потерей не являются. Калибровка 20 сентября, без модели, на записях `n8n/fixtures/clean-calibration/` (лекция ru j_0km8l8, совещание ru j_4ac6yf, субтитры VK j_7etqho, подкаст en j_d5fnkh; немецкий j_2fyciu – только контроль, списка паразитов нет): дефектных кусков – где исправление вернуло целую единицу – 26 (лекция 7, совещание 8, VK 5, подкаст 6), честных 16 (лекция 1, VK 7, подкаст 8); куски без повтора никем не проверены, поэтому их потерянные единицы размечены чтением – все шесть оказались шумом (перефраз, написание, заикание, обрывок на границе куска), кроме VK 6/13, спорного хвоста, который вне обоих классов. 92 – середина между 90% (максимум дефектных, если подкаст 7/14 при 98% отдать пункту (б)) и 95% (минимум честных). 10 – на одно слово больше самого длинного шума честных кусков: заикания, перефразы и обрывки на границе не длиннее 9 содержательных слов, а у каждого дефектного куска есть потерянная единица от 15 слов. Поэтому на этих записях доля к длине ничего не добавляет – она сетка на случай многих коротких потерь. Известное ложное срабатывание обоих пунктов, не лечится: адрес, сокращение или числительное, произнесённые по буквам и нормализованные моделью по промпту («work o s dot com» → «workos.com», «двадцатого» → «20-го» при smart_format), связки не совпадают; цена – одна коррекция. До 20 сентября единица была строкой сегмента, минимум 4 слова, порог 90% по единственному честному куску j_bj7lkh. Правило – жгут, не лечение: причина (модель на clean выбрасывает содержание – на русском первая попытка удерживает 42–66% на лекции и 47–76% на совещании) лечится отдельно, размером куска, промптом и моделью.
11. Пустой ответ `clean` (жёсткое, с 20 сентября). Промпт разрешает `paragraphs: []` на куске без речи, поэтому пустой массив невалиден только когда во входе куска есть речь – не меньше 20 слов после CONTEXT, примерно одно предложение (сторож транскрибации уже отказывает записям тише 20 слов в минуту). На первой попытке – исправление, на второй – существующий rule-based fallback `Clean chunk done`, задача идёт дальше. Второй слой в `Clean done`: если после всех кусков `transcript.clean` пуст, задача падает с `llm_failed` «clean produced no text» – до 20 сентября выполнение в этом месте заканчивалось «успехом» без единого item на `Map chunks`, и задача висела в `processing` до `MAX_JOB_MINUTES` (j_jppvgs).

Жёсткость правил. Структурные правила (пп. 1, 2, 4, 7, 8: JSON по схеме, таймкоды из абзацев, цитаты дословные, `structure` без дыр, перевод цитат) – после неудачного повтора блок `failed`, для `digest` это `failed` задачи. Стилевые правила (п. 9 и мета-зачин `tldr`: родовые заголовки, мета-глаголы, пересказ спикера, тезис-перечисление, общие формулировки в `critique.weak[].issue`; п. 10, удержание `clean`) – после неудачного повтора ответ принимается, задача не роняется, нарушения записываются в `jobs.meta.quality_warnings` как `{ stage, block?, message }`. В `result` они не попадают.

## 10. Решения

- Диаризация: у Deepgram включена, но с нумерацией внутри куска (см. п. 3). Сквозная нумерация – следующий шаг, скорее всего через отказ от нарезки для Deepgram (он берёт длинные файлы целиком).
- Перевода транскрипта целиком нет (см. 1.1); язык результата как явная функция – следующий цикл.
- Промпты: инструкции на английском, требование к языку вывода и примеры – явно в промпте. Промпты лежат в репозитории отдельными файлами, версионируются вместе со `schema_version`.
